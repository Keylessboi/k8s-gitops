# Known pre-existing Jobs and CronJobs without a wait-* initContainer.
#
# WHY A BASELINE AND NOT A FIX. When check-invariants.py was written it found
# eight of these. One (backup-freshness) was new in the same change and was
# fixed properly. The seven below predate the check, are currently working, and
# each needs its own verification to fix safely.
#
# Failing CI on all seven the day the check lands is how a check stops being
# read - the same reasoning .yamllint.yaml gives for tuning rules to the style
# the repo already uses rather than shipping a 900-finding backlog. So the debt
# is RECORDED here, visibly, and the check protects every NEW Job from day one.
#
# This file should only ever shrink. Removing a line is the fix; the checker
# fails if a name here no longer has a finding, so a stale baseline cannot
# quietly hide a job that was deleted or already fixed.
#
# To clear one: add a wait-* initContainer that polls whatever it connects to
# first (see apps/databases/pgdump-cronjob.yaml for the pattern), or - if the
# pod genuinely makes no early network call - annotate it with
# homelab/no-wait-init and delete its line here.
#
# Risk is not uniform. Ranked by how much a lost race costs:
#
#   lidarr-mass-search-a/b  a ~40-day catalogue build; a lost race at startup
#                           wastes the whole run. Highest value to fix.
#   vaultwarden-data-backup writes to MinIO. Same shape as the pgdump failure.
#   immich-extensions       runs once at install against Postgres.
#   pelican-admin           runs once, calls the Pelican API.
#   beets-import            hourly and idempotent; a lost run costs an hour.
beets-import
immich-extensions
pelican-admin
vaultwarden-data-backup

# Found 2026-09-30, when the liveness check (CHECK 3) landed and the whole file
# was re-run. These five are NOT "pre-existing" in the sense the header above
# means - they are Jobs added after this baseline was written, and they had been
# failing CI on every push to main for days. Nobody saw it, which is the same
# silent-failure shape this whole file exists to prevent: a red check that never
# turns green stops being read, and then a real finding looks like the usual
# noise.
#
# They are baselined rather than blind-fixed because each makes a genuine early
# network call and a wait-* initContainer has to poll the RIGHT target, which is
# a per-job decision:
#
#   seed-reaper              python3 -> QBIT_URL (qBittorrent) on its first line.
#                            Wait on the qBittorrent webui /api/v2/app/version.
#   nextcloud-upload-sweep   the very first call is `apk add curl findutils coreutils`,
#                            i.e. a call to an ALPINE MIRROR, before it reaches
#                            Nextcloud or qBittorrent at all. Needs thought, not just
#                            a wait for the app: the mirror is the first hop.
#   beets-replaygain-backfill reads and rewrites local files via ffmpeg; the open
#                            question is whether beets touches the network at all on
#                            this path. If it does not, this one is an annotation
#                            (homelab/no-wait-init) and not an initContainer.
#   games-mount-scan         runs kubectl, so it calls the API server on its first
#                            action. Wait on the apiserver, or annotate if the
#                            installed kubectl retries.
#   notesnook-s3-setup       configures MinIO with the mc client against the MinIO
#                            Service; wait on MinIO's /minio/health/live.
#
# Deleting a line here is the fix.
# ---------------------------------------------------------------------------
seed-reaper
nextcloud-upload-sweep
beets-replaygain-backfill
games-mount-scan
notesnook-s3-setup
